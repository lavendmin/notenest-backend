# NB1 전환 게이트 — LOB 삭제 전 "S3 가 DB LOB 를 실제로 대체하는가"

검증일: 2026-09-25~26 / 코드: `da3129b` / 버킷: `notenest-media` (ap-northeast-2) / 상태: 백필 완료, LOB 아직 존재
목적: LOB 컬럼을 지우기 전에 객체 저장소만으로 기능이 성립하는지 기록한다. 이 게이트를 모두 통과해야 LOB 삭제 단계로 넘어간다.

## 1. 백필 결과 게이트

| 조건 | 결과 | 근거 |
|---|---|---|
| 백필 실패 곡 0 | ✅ 0 | [백필 기록](nb1-backfill.md) |
| 커버 키 500 / 전체 데모 키 500 / 미리듣기 키 0(기존 곡 허용) | ✅ 500 / 500 / 0 | 백필 기록 교차 확인 |
| S3 객체 누락·크기 불일치·SHA-256 불일치 0 | ✅ 0 / 0 / 0 | 백필 대조 1,000객체 |
| 재실행 시 신규 업로드 0 | ✅ 대상 0, 업로드 0 | 1·2차 실행 로그 보존 |

| 실제 legacy 객체 HEAD 성공, 크기·체크섬 = DB | ✅ 커버 307,200B·전체 데모 3,145,728B, SHA-256 이 DB `SHA2()` 와 일치 | 아래 A |

| API 가 가리키는 키 = DB 객체 키 | ✅ 상세 coverUrl·다운로드 url 이 DB 키를 가리킴 | 아래 A |

### A. legacy 객체 (시드 곡 1곡)
- 로그인 상세: `coverUrl` 이 DB 커버 키를 가리키고 base64 `image` 는 없다. 키가 있으면 LOB fallback 을 쓰지 않는다. 미리듣기가 없는 기존 곡이라 `previewUrl` 도 없다.
- 판매자 다운로드: 파일명 `seed song 1(부제 1).mp3`. 형식을 판별할 수 없는 시드라 mp3 로 대체된다.

## 2. 전환 상태 E2E (LOB 존재, 실제 S3)

| 조건 | 결과 | 근거 |
|---|---|---|
| 새 곡 등록: 커버·미리듣기·전체 데모 저장 | ✅ | [E2E](nb1-real-s3-e2e.md) 1 |
| 목록은 커버 URL 만 | ✅ | E2E 2 |
| 상세는 미리듣기 URL 만(전체 데모 경로 없음), 비로그인 401 | ✅ | E2E 4 |
| 객체 키·전체 데모 비노출 | ✅ 목록·상세에 full-demo 0회 | E2E 2·4 |
| 판매자 전체 데모 URL 발급 | ✅ | E2E 5 |
| **결제 완료 낙찰자 발급** | ✅ 입찰 전 403 → `COMPLETED` 입찰 후 5분 URL, GET 200, 바이트 일치 | 아래 B |
| **무관한 사용자 거부** | ✅ 403 | 아래 B·E2E 5 |
| 수정 시 새 객체로 교체 후 이전 객체 삭제 | ✅ 옛 커버 URL 404 | E2E 6 |
| **첫 입찰 후 전체 데모 교체 거부** | ✅ 409, 키 불변, 기존 객체 계속 제공 | 아래 B |
| **첫 입찰 후 곡 삭제 거부** | ✅ 409 | 아래 B |
| **잘못된 형식 거부** | ✅ 미리듣기에 WAV → 400 | 아래 B |
| **크기 초과 거부** | ✅ 미리듣기 6MB → 400("5MB 이하"), 전체 데모 100MB 초과 → 413 | 아래 B |
| 거부된 요청은 곡을 만들지 않음 | ✅ 0행 | 아래 B |
| presigned URL 만료·재발급 | ✅ 314초 뒤 `Request has expired`, 재발급 200 | E2E 3 |

B 의 결제 완료 낙찰자는 실제 결제 흐름을 돌리지 않았다. 테스트 곡에 `COMPLETED` 입찰 행을 SQL 로 넣어 만들었다. 검증 대상은 결제가 아니라 접근 정책(`Bid.status=COMPLETED`)이다. 검증이 끝난 뒤 테스트 입찰과 곡은 지웠다.
